## 3. الحدود المعروفة (مقصودة أو مؤجلة)

### 3.1 حدود تلجرام (لا يمكن تجاوزها)

| # | الحد | الأثر |
|---|---|---|
| L1 | لا عناوين (`h1..h6`) | العناوين تُعرض عريضة + تحذير |
| L2 | لا قوائم (`ul/ol/li`) | `• ` و`1. ` كنص + تحذير |
| L3 | لا جداول | كتلة `pre` أحادية المسافة + تحذير |
| L4 | لا صور في النص | رابط/إيموجي + تحذير (الصور تحتاج `sendPhoto`) |
| L5 | 4096 وحدة UTF-16/رسالة | تقسيم تلقائي |
| L6 | ~100 كيان/رسالة | تقسيم حسب ميزانية الكيانات |
| L7 | ~30 رسالة/ثانية، ~20/دقيقة/قناة | backoff على 429 |
| L8 | **لا تعديل** منشور بعد النشر (الحذف مدعوم) | تعديل المنشور يتطلب إعادة حساب الإزاحات والتقسيم — خارج النطاق |

### 3.2 حدود معمارية متعمدة

| # | الحد | السبب | التحسين المستقبلي |
|---|---|---|---|
| L9 | Rate limiting في الذاكرة | D3 (لا جدول) | Redis أو جدول `rate_limit_hits` |
| L10 | حالة معاينة البوت في الذاكرة | بساطة | Redis (ضروري لأكثر من نسخة) |
| L11 | Polling لا يدعم أكثر من نسخة | قيد تلجرام | استخدم webhook |
| L12 | لا طوابير نشر | النشر متزامن وسريع | BullMQ للتحجيم |
| L13 | JWT بلا إبطال فردي | يكفي بنطاقه | جدول sessions/revocation |
| L14 | تحرير القنوات: دور `owner` فقط فعليًا | مالك القناة هو من يربطها | دعوة محررين |
| L15 | لا جدولة نشر (scheduling) | خارج النطاق | جدول `scheduled_publications` + cron |
| L16 | لا تحليلات/إحصاءات قناة | خارج النطاق | Telegram Analytics / جمع مشاهدات |

### 3.3 ديون تقنية معروفة

| # | البند | الأثر |
|---|---|---|
| T1 | 3 ثغرات npm في تبعيات تطويرية متعدية (1 moderate, 2 critical) | لا أثر على وقت التشغيل — راجع `npm audit` |
| T2 | لا اختبارات E2E كاملة عبر متصفح لمسار البوت | البوت مختبَر على مستوى `handleUpdate` |
| T3 | لا اختبارات أداء/حمل | يُنصح بها قبل التحجيم |
| T4 | الرسائل النصية في `texts.js` مكتوبة يدويًا بالعربية والإنجليزية | لا تُرجمت آليًا |

## 4. ما هو **ليس** ضمن النطاق

- نشر على فيسبوك/تويتر/لينكدإن.
- تحرير جماعي للفريق.
- استيراد من CMS.
- تحليلات متقدمة (مشاهدات، نقرات).
- دفع/اشتراكات.
- تطبيق موبايل أصلي (Native).
- ترجمة آلية للمحتوى.

## 5. تقييم الجاهزية

| المحور | التقييم |
|---|---|
| جودة الكود وبنيته | عالية — فصل صارم، بلا منطق مكرر، JavaScript نقي |
| تغطية الاختبارات | جيدة جدًا للـ Backend والمحرك، جيدة للواجهة |
| الأمان | جيد جدًا — التحقق والفحص الحي ومنع التكرار والعزل |
| جاهزية الإنتاج | **جاهز بعد**: HTTPS، ونسخ احتياطي (البوت والنشر مُختبَران على تلجرام حقيقي) |
| التوثيق | كامل — README/EXTERNAL_SETUP/DEPLOYMENT/SECURITY/architecture |

**الحكم:** النظام **مُتحقَّق منه على تلجرام الحقيقي**: التوكن، استقبال التحديثات، ربط القناة بفحص حي، النشر الفعلي، وتسجيل النتائج في القاعدة — كلها نجحت (19/19). جاهز للتشغيل بمجرد تعبئة `.env` — لا حاجة لتغيير أي كود. المتبقي هو **نشر الواجهة على HTTPS** ليعمل Mini App داخل تلجرام.
