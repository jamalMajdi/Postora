# تشخيص: «تعذّر التحقق من بيانات تلجرام» في Mini App

> **التشخيص:** خطأ في التحقق من توقيع `initData` على الخادم.
> **السبب الجذري:** حقل `signature` الذي يضيفه تلجرام في العملاء الحديثة كان يُستثنى من حساب التوقيع.
> **الحالة:** ✅ **مُصلَح ومُختبَر** (2026-10-30).

---

## 1. العَرَض

عند فتح Mini App من داخل تلجرام تظهر شاشة:

```
        [P]
┌───────────────────────────┐
│ تعذّر التحقق من بيانات تلجرام. │
└───────────────────────────┘
      [ إعادة المحاولة ]
```

## 2. تتبّع الرسالة في الكود

| الطبقة | الملف | الرمز |
|---|---|---|
| نص الرسالة | `packages/shared/src/errors.js:62` | `AUTH_INVALID_INIT_DATA: 'تعذّر التحقق من بيانات تلجرام.'` |
| شاشة الخطأ | `apps/miniapp/src/App.jsx:76` | `getUserMessage(error.code, …)` |
| مصدر الخطأ | `apps/server/src/telegram/initDataValidator.js` | `throw new AppError(ErrorCode.AUTH_INVALID_INIT_DATA)` |

⇒ الرسالة تُعرض **فقط** عندما يُرجع الخادم `AUTH_INVALID_INIT_DATA`
(وليست `AUTH_MISSING_INIT_DATA` التي تظهر في المتصفح، ولا `AUTH_EXPIRED_INIT_DATA`).

## 3. السبب الجذري

تلجرام يوقّع `initData` بخوارزمية **HMAC-SHA256** حيث
`data_check_string` = **كل الحقول الواردة ما عدا `hash` فقط**.

العملاء الحديثة (تلجرام Web/Desktop/Mobile) أصبحت تضيف حقل **`signature`**
(توقيع Ed25519 للتحقق من طرف ثالث).

كان الكود يستثني **حقلين**:

```js
// ❌ قبل الإصلاح
if (key === 'hash' || key === 'signature') continue;
```

استثناء `signature` يخصّ **مسار Ed25519 وحده**، وليس التحقق بتوكن البوت.
النتيجة: التوقيع المحسوب على الخادم لا يطابق توقيع تلجرام **أبدًا** متى ما كان
`signature` موجودًا ⇒ رفض كل تشغيل حقيقي.

### إعادة إنتاج مؤكدة

بنفس البيانات، الفرق الوحيد هو وجود `signature`:

```
بدون signature  → ✅ نجح التحقق
مع signature    → ❌ AUTH_INVALID_INIT_DATA    ← نفس رسالة العطل
```

> **لماذا لم تكشفه الاختبارات القديمة؟**
> لأن مولّد الاختبار `buildInitDataForTests` لم يكن يُضيف `signature` أصلًا —
> فكان الاختبار يُوقّع ويتحقق بنفس الافتراض الخاطئ، فيبقى أخضر بينما الواقع معطّل.
> هذا نفس الخطأ الذي وقعت فيه مشاريع أخرى (موثّق في عدة PRs عامة).

## 4. الإصلاح

```js
// ✅ بعد الإصلاح — apps/server/src/telegram/initDataValidator.js
// تلجرام يوقّع كل الحقول الواردة عدا hash. حقل signature يبقى داخل النطاق.
if (key === 'hash') continue;
```

### التحقق من الإصلاح

| الاختبار | النتيجة |
|---|---|
| إعادة إنتاج (سكربت) | ✅ `مع signature → نجح التحقق` |
| اختبارات `initData.test.js` | ✅ **12/12** (كانت 9، أُضيفت 3 انحدار) |
| اختبار الانحدار على الكود القديم | ❌ **يفشل** (`1 failed`) — يثبت أنه يحمي فعليًا |
| مسار HTTP كامل `/api/auth/session` | ✅ `200` + JWT مع وبدون `signature` |
| الاختبارات الكلية | ✅ **158/158** (كانت 155) |

### اختبارات الانحدار المضافة

1. **يقبل** `initData` حقيقية تحتوي `signature` (HMAC بتوكن البوت).
2. **يرفض** `initData` ذات `signature` معدّل بعد التوقيع ← يثبت أن `signature` داخل نطاق التوقيع (لا ثغرة أمنية).
3. **حذف** `signature` من حمولة موقّعة معه يُبطل التوقيع ← يثبت أنه ليس حقلًا حرًّا.

## 5. تشخيص آمن مضاف (لكشف أي مشكلة مستقبلًا فورًا)

عند الرفض، يُسجَّل الخادم سببًا تشخيصيًا **بلا أي بيانات حساسة**
(لا `initData`، لا `hash`، لا توكن):

```json
{
  "level": 40,
  "authFailure": "AUTH_INVALID_INIT_DATA",
  "reason": "hash_mismatch",
  "hasSignatureField": true,
  "authDateAgeSeconds": 3,
  "msg": "initData rejected"
}
```

ويُرجَع في الاستجابة أيضًا (`error.details.reason`) ليعرف العميل السبب:

```json
{
  "ok": false,
  "error": {
    "code": "AUTH_INVALID_INIT_DATA",
    "message": "تعذّر التحقق من بيانات تلجرام.",
    "details": { "reason": "hash_mismatch", "hasSignatureField": false, "authDateAgeSeconds": 93468859 }
  }
}
```

### كيف تقرأ التشخيص

| `reason` | المعنى | الحل |
|---|---|---|
| `hash_mismatch` + `ageSeconds` ضخم | `initData` قديمة/معاد استخدامها | أعد فتح التطبيق من تلجرام |
| `hash_mismatch` + `hasSignatureField: true` | **كان هذا العطل** | حدّث المشروع (مُصلَح) |
| `hash_mismatch` + عمر طبيعي | **`BOT_TOKEN` في الخادم ≠ توكن البوت الحقيقي** | صحّح `BOT_TOKEN` وأعد التشغيل |

## 6. ماذا تفعل الآن

```bash
# 1) حدّث الملفات (الحزمة الجديدة تحتوي الإصلاح)
npm install

# 2) شغّل الاختبارات — يجب أن ترى 158
npm test

# 3) شغّل الخادم
npm run dev

# 4) افتح التطبيق من داخل تلجرام
```

**إن استمرت المشكلة بعد التحديث** فافحص السجل بحثًا عن `initData rejected`:

- إن ظهر `ageSeconds` كبيرًا ⇒ أعد فتح التطبيق (لا تستخدم رابطًا قديمًا).
- إن كان العمر طبيعيًا ⇒ **التوكن في الخادم مختلف عن توكن البوت**.
  تحقق أن `BOT_TOKEN` في `.env` هو نفسه التوكن الذي فتحت به التطبيق
  (تأكد أنك لا تستخدم توكنًا قديمًا أُبطل من BotFather).

## 7. الدرس المستفاد

**الاختبارات التي تُوقّع وتتحقق بنفس الافتراض لا تكشف أخطاء الافتراض.**
الحل المطبَّق: اختبار انحدار يُحاكي **الحمولة الحقيقية** كما يرسلها تلجرام
(بما فيها `signature`)، وليس الحمولة التي نتخيلها.
