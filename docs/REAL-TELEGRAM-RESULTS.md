## 5. خلل حرج كشفه الاختبار الحقيقي (وأُصلح)

### العَرَض
أرسل المستخدم `/start` فلم يحدث شيء، ولم يظهر أي خطأ.

### السبب الجذري
ملف `.env` في بيئة التطوير يحتوي:

```env
TELEGRAM_API_BASE_URL=http://127.0.0.1:8081   # خادم تلجرام الوهمي للاختبار المحلي
```

هذا المتغير يوجّه كل نداءات Bot API إلى **الخادم الوهمي المحلي** بدل تلجرام الحقيقي.
فالبوت كان «يعمل» ويطبع `bot started (polling)` — لكنه يستمع على خادم وهمي **لا يصله أي تحديث حقيقي**.

**خطورة الخلل:** صامت تمامًا. لا خطأ، لا تحذير، لا فشل — البوت يبدو سليمًا وهو معطّل فعليًا.

### الإصلاح
1. **تشغيلي:** ضبط `TELEGRAM_API_BASE_URL=https://api.telegram.org` صراحة في بيئة التشغيل الحقيقية.
2. **توثيقي وقائي** (أُضيف الآن):
   - تحذير صريح في `.env.example` بأن المتغير **للاختبار فقط** ويجب أن يبقى معلّقًا.
   - بند في جدول استكشاف الأخطاء في `README.md`: «البوت لا يرد بلا أي خطأ ⇒ تحقق من `TELEGRAM_API_BASE_URL`».

### الدليل على الإصلاح
```
قبل:  pending_update_count = 5   (تحديثات عالقة لا يعالجها أحد)
بعد:  pending_update_count = 0   (البوت استهلكها)
      users = 1 (Jemo09)
```

## 7. ملاحظات أمنية

1. **التوكن الذي أُرسل في المحادثة يجب إبطاله فورًا:** BotFather ← `/mybots` ← `@Postora_1bot` ← API Token ← **Revoke**.
2. التوكن **لم يُكتب في أي ملف داخل المشروع** — وُضع في `/tmp/pstoken` (خارج مجلد التسليم، صلاحيات `600`) وبيئة تشغيل مؤقتة.
3. تم فحص استجابة `POST /api/auth/session` للتأكد من عدم تسريب أي جزء من التوكن: **نظيفة**.
4. `docs/`, `README.md`, `TEST_RESULTS.md`, `.env.example` — **لا تحتوي أي سر**.
