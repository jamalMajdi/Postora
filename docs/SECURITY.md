# نموذج التهديد والضوابط الأمنية (SECURITY)

> هذه الوثيقة تصف **ما نحمي منه**، و**كيف**، و**ما يبقى غير محمي**.

## 1. الأصول المحمية

| الأصل | لماذا مهم |
|---|---|
| Bot Token | من يملكه يتحكم بالبوت كاملًا (قراءة/إرسال باسمه) |
| حق النشر في قنوات المستخدمين | نشر محتوى غير مرغوب باسم صاحب القناة |
| محتوى المسودات | قد يحتوي محتوى غير منشور بعد |
| بيانات المستخدمين | معرّفات تلجرام وأسماء |
| سر JWT | من يملكه يزوّر جلسات |

## 2. نموذج التهديد

| # | التهديد | السيناريو | الضابط | مُختبَر؟ |
|---|---|---|---|---|
| T1 | تسريب التوكن | رفعه لـ Git أو كشفه في الواجهة | `.env` فقط + `.gitignore` + لا endpoint يُرجعه + redaction في السجلات | ✅ |
| T2 | انتحال مستخدم | تعديل `user.id` في الطلب | الهوية من `initData`/JWT فقط؛ حقول الطلب تُتجاهل | ✅ |
| T3 | تزوير initData | توليد توقيع مزيف | HMAC-SHA256 رسمي (WebAppData) + `timingSafeEqual` | ✅ |
| T4 | إعادة استخدام initData مسرَّبة | تشغيل initData قديم | فحص `auth_date` (حد أعلى 24 ساعة افتراضيًا) + JWT قصير | ✅ |
| T5 | IDOR — الوصول لمسودة/قناة الغير | تغيير UUID في المسار | كل استعلام مقيّد بـ `user_id` من الجلسة | ✅ |

| T7 | بوت بلا صلاحية نشر | أدمن بلا `can_post_messages` | فحص `can_post_messages`/`can_send_messages` | ✅ |
| T8 | **نشر مزدوج** | ضغط مزدوج / إعادة محاولة شبكة | `idempotency_key UNIQUE` + انتقال ذرّي + استهلاك حالة المعاينة | ✅ |
| T9 | HTML/سكربت خبيث | `<script>` في Markdown | `html:false` + هروب `& < >` + قائمة بيضاء للوسوم | ✅ |
| T10 | رابط بسياق خطير | `[x](javascript:...)` | قائمة بيضاء للمخططات (http/https/tg/mailto) | ✅ |
| T11 | حقن SQL | `'; DROP TABLE` في حقل | Parameterized queries فقط | ✅ |
| T12 | ملف ضار | ملف ثنائي/ضخم بامتداد `.md` | تحقق امتداد + حجم قبل التنزيل + UTF-8 صارم + رفض `\0` | ✅ |

| T15 | webhook مزيف | إرسال تحديثات مزورة | مقارنة `secret_token` | ⚠️ كود مكتوب، غير مختبَر HTTPS |
| T16 | تسريب في السجلات | طباعة initData/توكن | Pino `redact` + لا نسجّل محتوى المستخدم | ✅ |
| T17 | أزرار قديمة (replay) | الضغط على تأكيد قديم | حالة المعاينة تُستهلك فورًا + حالة الطلب في القاعدة | ✅ |

## 3. ضوابط مطبقة بالتفصيل

### 3.1 مصادقة Mini App

```js
// apps/server/src/telegram/initDataValidator.js
secret_key = HMAC_SHA256("WebAppData", bot_token)
hash       = HMAC_SHA256(secret_key, data_check_string)
```

- `data_check_string` = كل الحقول (عدا `hash`) مرتبة أبجديًا.
- نقارن بـ `timingSafeEqual` (لا مقارنة نصية عادية).
- نرفض `auth_date` أقدم من `INIT_DATA_MAX_AGE_SECONDS`.
- نرفض تواريخ مستقبلية بأكثر من 5 دقائق (انحراف ساعة).

### 3.2 الصلاحيات: مبدأ "الفحص الحي"

قاعدة البيانات **ليست** مصدر قرار أمني. التسلسل في `executePublication`:

```
1. ملكية في القاعدة       → بوابة أولى سريعة (رفض مبكر)
2. انتقال حالة ذرّي       → يمنع التكرار
3. getChat   (حي)         → القناة موجودة؟
4. getChatMember(bot)     → أدمن + can_post_messages؟
5. getChatMember(user)    → مالك/أدمن الآن؟
6. sendMessage ×N         → النشر
```

أي فشل → حالة `failed` + سبب عربي + تُسجّل الرسائل التي نجحت (لا إعادة صامتة).

### 3.3 منع التكرار

| الطبقة | الآلية | ما تمنعه |
|---|---|---|
| الواجهة | تعطيل الزر أثناء العملية | النقر المزدوج |
| البوت | حذف حالة المعاينة فور الضغط | الضغط على تأكيد قديم |
| API | `idempotency_key` UNIQUE | إعادة إرسال نفس الطلب |
| القاعدة | `UPDATE ... WHERE status='pending'` ذرّي | تنفيذ متزامن من عمليتين |
| المستخدم | تحذير التكرار (10 دقائق) + `allowDuplicate` | النشر المتعمد بالخطأ |

### 3.4 تطهير HTML

```js
markdown-it({ html: false })     // HTML الخام لا يُفسَّر
escapeHtml()                     // & < > في كل نص
entitiesToHtml()                 // وسوم من قائمة بيضاء فقط
```

في React: `dangerouslySetInnerHTML` تُستخدم **فقط** مع `message.html` المُولَّد من المحرك بعد التطهير — لا مع أي مدخل خام.

## 4. ما لا نحمي منه (حدود صريحة)

| الحالة | التوضيح |
|---|---|
| سرقة جهاز المستخدم | من يملك الجلسة المفتوحة في تلجرام يملك الحساب |
| بوت مُخترق على مستوى تلجرام | خارج نطاق سيطرتنا |
| قناة محذوفة | نفشل بوضوح، لا نعيد المحاولة صامتًا |
| محتوى ضار نشرَه صاحب القناة نفسه | Postora ينشر ما يؤكده المالك |
| XSS في واجهة تلجرام | نحن نطهّر، لكن تلجرام مسؤول عن WebView |
| DDoS على مستوى الشبكة | يحتاج Cloudflare أو ما يعادله أمام الاستضافة |

## 5. إجراءات عند الاشتباه في تسريب

1. **توكن البوت:** BotFather ← `/mybots` ← API Token ← **Revoke** → ضع الجديد في `.env` → أعد تشغيل الخادم.
2. **JWT_SECRET:** غيّره → **كل الجلسات تُبطل فورًا** (المستخدمون يعيدون فتح التطبيق).
3. **DATABASE_URL:** غيّر كلمة السر من لوحة الخدمة → حدّث `.env` → أعد التشغيل.
4. **`.env` مرفوع لـ Git؟** `git rm --cached .env` + أعد توليد **كل** المفاتيح (اعتبر القديمة مسرَّبة) + إن كان المستودع عامًا، احذفه وأعد إنشاءه نظيفًا (التاريخ يبقى قابلًا للاستخراج).
